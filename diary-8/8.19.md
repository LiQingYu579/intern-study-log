## 绿盟 RSAS API 学习与接口调用实践

## 工作内容

主要结合绿盟 RSAS API 接口文档，学习漏洞扫描任务从创建、查询状态到获取扫描结果的完整调用流程，并使用 Python 做了简单的接口模拟实践，为后续实现“工单传入 IP 后自动触发漏洞扫描”做准备。

## 学习与实践过程

### 1. 学习 API 基础知识

结合接口文档了解了 URL、GET/POST、form-data、JSON、HTTP 状态码、Basic Auth 等基础概念，并理解了绿盟接口中的 `ret_code`、`ret_msg` 等业务返回字段。

### 2. 梳理漏洞扫描流程

重点学习了几个核心接口：

- 创建漏洞扫描任务：`/api/task/vul/create`
- 查询任务状态：`/api/task/status/{task_id}`
- 获取扫描结果：`/api/report/task/{task_id}`

理解了扫描任务创建成功后会返回 `task_id`，之后需要根据任务 ID 定时查询扫描进度，等任务完成后再获取最终漏洞结果。

### 3. 理解异步任务和轮询

漏洞扫描需要一定时间，不能创建任务后立即获取结果，因此需要通过“创建任务 → 获取 task_id → 定时查询状态 → 扫描完成 → 获取结果”的方式处理。

同时了解了暂停、继续、停止、任务列表等其他任务管理接口。

### 4. Python 接口调用实践

使用 Python 编写了简单的模拟程序，先模拟绿盟返回扫描任务和漏洞结果，之后进一步使用 `requests` 实现真实的 HTTP 请求过程。

在本地分别运行了：

- `fake_rsas_server.py`：模拟绿盟 RSAS API 服务
- `rsas_client.py`：模拟调用绿盟接口的客户端

最终成功跑通：

`创建扫描任务 → 返回 task_id → 查询 20%/55%/85%/100% 进度 → 获取扫描结果`

并成功获取模拟的高危、中危、低危漏洞数量。

### 5. Python 环境整理

过程中处理了 Python 解释器和虚拟环境问题，使用 `.venv` 为当前项目单独管理依赖，并安装了 `requests` 等库。同时重新整理了项目文件目录，避免代码文件放到 `.vscode` 配置目录中。

## 总结

今天从单纯阅读绿盟 API 文档，进一步实际跑通了一个简化版的漏洞扫描接口调用流程，对 `task_id`、异步任务、轮询、HTTP 请求以及 JSON 返回数据有了更直观的理解。

目前已经基本理解了绿盟侧：

`工单 IP → 创建扫描任务 → 查询扫描进度 → 获取漏洞结果`

这一核心流程。
