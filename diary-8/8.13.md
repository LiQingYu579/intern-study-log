# 绿盟漏扫数据整理 — 负责人核对

## 工作内容

今天主要工作是整理绿盟漏洞扫描结果，核对两张扫描表中缺失的"负责人"信息。

涉及两张表：

- **Web 漏洞扫描明细统计**（90 个站点，535 个漏洞）
- **弱口令专项扫描明细统计**（611 台主机，2 个弱口令）

两张表中多处"负责人"列为空，需要根据「绿盟漏扫-扫描范围-v2.xlsx」中的「两院应用」和「公有云 IP」两个 sheet，逐条匹配每个网段下对应业务系统的归属人。

## 核对过程

### 1. 理解表格逻辑

首先需要搞清楚"负责人"的填写规则：这里填的是该网段上跑的**业务系统的实际归属人**，不是网络管理员。例如服务器网段的负责人是各业务方（财务、科研、公文等），而不是管网络基础设施的人。

### 2. 逐条匹配

对每个缺失的网段，在「两院应用」sheet 中找到该网段下的所有业务系统，按 **IP → 用途 → 负责人** 的链路匹配。对于云服务网段，还需要用「公有云 IP」sheet 区分 scope 内外。

### 3. 遇到的难点

- **公网出口网段**：一个网段下跑了多个业务系统，分属不同部门，不能只填一个人
- **云服务 IP**：需要区分 scope 内外。scope 内的 IP 在「公有云 IP」sheet 中有记录，scope 外的只在「两院应用」表中出现。同一台主机上可能跑了多个端口的服务，分属不同的人
- **办公无线和哑终端网段**：属于公共网络基础设施，没有单一业务归属人，按已有行的逻辑填网络管理员

### 4. 最终结果

通过逐条对照 Excel 原始数据，将每个 IP 的业务归属和负责人一一对应，完成了两张表所有缺失负责人的补全。

## 感受

这个工作看起来简单，实际很容易出错。过程中反复犯了几次错误：

- 一开始没仔细看，把已填的行也当成缺失
- 用同网段推断负责人，而不是逐条匹配 IP，导致张冠李戴
- scope 内外判断搞反，把在公有云 IP 清单里的 IP 错放到 scope 外
- 共享主机上多个端口分属不同人，漏掉了部分负责人

最后通过逐条对照 Excel 原始数据，把每个 IP 的业务归属和负责人一一对应，才得到正确结果。
