## 绿盟扫描功能增强 — 工作记录

今天继续推进**绿盟扫描能力之后的功能增强方案**，重点验证基于 MOVERY 检测结果进行二次补丁状态核验的可行性。

### 主要完成内容

- 继续完善已经冻结的 **V7 补丁核验方案**，开始进行新的盲测泛化验证，避免只在前期 Redis 案例上得到较好的结果
- 选取新的 CVE 和真实开源项目版本，构建 PRE/POST 漏洞修复状态进行测试
- 排查 Linux 项目运行时出现的 sparse-checkout、历史 commit checkout 等问题，确认这些属于实验执行环境问题，而不是 V7 算法本身的问题
- 将 Linux 项目的执行方式改为 **Git worktree** 后成功跑通，6 条此前未完成的报警全部进入 V7 进行核验
- 最终完成当前 Stage 5-A 盲测，**11 条报警全部完成核验**，结果为：

| 结果 | 数量 |
|------|------|
| KEEP | 6 条 |
| REVIEW | 4 条 |
| FILTER | 1 条 |
| 覆盖率 | 100% |

- 进一步发现一条值得重点分析的误过滤案例：**CVE-2015-3886**。该案例属于真实漏洞状态，但 V7 判断为已补丁状态，因此开始查看其官方修复代码和补丁差异
- 初步发现该案例的补丁主要涉及**控制条件变化**，现有补丁证据可能没有充分区分"漏洞版本中已经存在的代码"和"补丁真正新增的控制上下文"

已经完成 V7 第一阶段盲测以及执行问题排查。目前正在进一步分析唯一的误过滤案例，判断是否可以从**补丁证据方向性、控制上下文等方面继续增强现有方案**。

### 明日计划

继续分析 CVE-2015-3886 / Signature 2018 的补丁关键语句在 PRE、POST 版本中的差异，根据分析结果决定下一步的功能增强方式。
