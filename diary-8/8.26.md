从重新安装 Cursor 开始，完成 AIPQ 项目的远程开发环境配置、代码仓库管理、出题调用统计、Sub2API 接入和真实简历测试，为后续业务功能开发打基础。

## 1. 重新搭建 Cursor 开发环境

重新安装并配置了 Cursor，安装 Codex 插件。

通过 Cursor Remote SSH 连接 Ubuntu 服务器，并打开项目目录：



## 2. 配置公司 Sub2API

在远程 Ubuntu 中配置了公司提供的 Sub2API，使 Codex 和 AIPQ 项目可以通过中转接口调用 GPT 模型。

项目的 API Key 保存在：

```text
.env
```

并确认：

- `.env` 已被 Git 忽略；
- API Key 没有提交到仓库；
- `.env.example` 只保留空配置示例；
- 项目调用和 Codex 调用可以在 Sub2API 后台区分。

## 4. 检查项目架构和出题流程

确认当前项目主要包含两条链路：

```text
面试端
 → Flask服务
 → 读取预生成题目
 → 学生答题
 → 保存语音和文字结果
```

```text
简历
 → 提取简历内容
 → 生成候选人画像
 → 并行生成4组题目
 → Reviewer审核
 → Validator检查
 → 保存题目文件
```

确认当前项目暂时没有完整的面试官管理端，后续仍需要实现简历上传、学生管理、题目分配和状态管理等功能。

## 5. 增加 Token 和调用指标统计

为出题链路增加了 Metrics 统计，记录：

- 各阶段使用的模型；
- 输入、输出和总 Token；
- HTTP 请求次数；
- 重试次数；
- 缓存命中情况；
- 各阶段调用耗时；
- 整体墙钟时间；
- Provider request ID；
- 任务成功或失败状态。

统计文件保存到：

```text
output/metrics/<request_id>.json
```

同时增加了并发隔离和隐私保护：

- 不记录简历正文；
- 不记录 Prompt；
- 不记录 API Key；
- 学生标识仅在配置 HMAC 密钥时保存脱敏值；
- 多名学生并发时不会串数据。

该功能已提交并推送：

```text
e949509 feat: add question generation usage metrics
```

## 7. 修复文本框型 DOCX 简历

使用自己的简历测试时，发现 Word 简历正文主要位于文本框中，原来的 `python-docx` 无法提取，程序报错：

```text
DOCX 中没有提取到文本
```

通过解析 DOCX 内部的 OOXML，增加了文本框内容提取能力，并处理：

- `w:txbxContent` 文本框；
- 多段文字；
- 表格和普通段落；
- Choice/Fallback重复内容；
- 损坏DOCX的安全异常。

自己的简历验证结果：

```text
提取字符数：2289
非空段落数：52
```

测试结果：

```text
111 passed, 60 subtests passed
```
