# AIPQ 项目接手开发、并发验证与面试闭环稳定性记录

## 阶段目标

在前期完成全程媒体保存、MP4 交付和单机资源优化的基础上，继续完成：

- 验证单台虚拟机的并发处理能力；
- 解决长视频转码、保存失败和状态不同步问题；
- 完善浏览器刷新、关闭和 Session 恢复；
- 增加截图型 DOCX 简历的 OCR 提取；
- 修复管理员归档和重新上传简历功能；
- 完善安全配置和正式上线前验证。

## 1. 完成长视频媒体实测

使用低码率配置完成了一次完整面试测试：

- 面试时长约 54 分钟；
- 共 326 个视频分片；
- 分片索引连续，无缺失；
- 最终 MP4 时长约 54 分钟；
- MP4 大小约 130MB；
- 视频编码为 H.264；
- 音频编码为 AAC；
- 浏览器播放、拖动和时间显示正常；
- Windows 下载后可以识别时长并拖动播放。

确认低码率配置能够显著降低单个学生的视频占用，550GB 磁盘可以支持批量保存。

## 2. 完善 MP4 转码和保存流程

继续修复长视频转码问题：

- 不再把 MediaRecorder 分片当成多个独立 WebM 文件拼接；
- 按顺序重建完整 WebM 流；
- 先 remux 为带 duration 和索引的中间容器；
- 再生成 H.264/AAC MP4；
- 通过 ffprobe 检查时长、视频轨道、音频轨道和编码；
- 短视频、缺轨道或时长异常时不再误判为成功；
- 原始分片、WebM 和音频在失败时继续保留。

同时增加持久化转码任务：

- 转码任务写入 SQLite；
- 支持 queued、running、succeeded、transcode_failed；
- Worker 重启后可以恢复任务；
- 重复点击“重试转码”不会创建重复任务；
- 转码状态不再依赖某个 Web 进程的内存；
- 管理员页面可以轮询转码进度。

## 3. 修复面试结果保存失败误报

此前学生结束面试后，前端可能因为等待视频 finalize 时间过长而显示“结果保存失败”，但后台实际已经保存成功。

现已调整为：

- 答题结果先独立保存；
- 视频 finalize 和转码进入后台任务；
- 网络超时后轮询 Session 状态；
- 只有后台明确返回失败时才显示保存失败；
- finish、finalize、重复点击和浏览器关闭流程均保持幂等；
- 媒体处理失败不会覆盖已经保存的答题结果。

## 4. 完善 Session 生命周期和刷新恢复

修复多个设备、刷新和重新开始面试时的状态问题：

- Session 与发布版本绑定；
- 旧的 completed/interrupted Session 不会被复用；
- 管理员可以针对当前发布版本开启新一轮面试；
- 学生刷新浏览器后恢复原 active Session；
- 恢复当前题目和已答题进度；
- 刷新后从正确的分片序号继续上传；
- 第二个浏览器标签页不会覆盖正在进行的录制；
- 迟到的 heartbeat 不会把 completed 状态改回 in_progress；
- 终态 Session 可以进行安全补偿完成或标记中断。

## 5. 修复学生端 TTS 和面试启动问题

针对开场白、背景材料和题目语音不同步的问题进行了修复：

- 统一兼容多个背景材料字段；
- 材料文字和 TTS 使用同一个 snapshot；
- 开场白、背景材料、题目语音严格串行播放；
- 旧音频事件不会推进新题；
- TTS 请求增加文本摘要和 Session 校验；
- 关闭旧缓存复用，避免朗读上一版本内容；
- 语音失败时显示“重试播报”或“文字继续”；
- 未获得明确操作前不会直接进入答题；
- 修复 TTS 因旧 Token 状态返回 409 的问题；
- 修复严格 CSP 导致设备检测按钮无响应的问题；
- 摄像头、麦克风和 MediaRecorder 失败时显示明确提示。

根据后续 pipeline 要求，当前 MP4 主媒体只保留摄像头和学生麦克风声音，数字人 TTS 作为现场播放内容，不作为学生答题证据混入主视频。

## 6. 增加截图型 DOCX 简历 OCR

发现部分简历是将截图直接插入 DOCX，普通文本提取无法读取图片内容，导致简历显示缺失或生成在提取阶段失败。

现已实现：

- 遍历 DOCX 中的 `word/media/` 图片；
- 使用本地 Tesseract OCR；
- 支持中文和英文识别；
- 合并普通文字、表格、文本框和 OCR 内容；
- 对 OCR 结果进行段落去重；
- 对明显连续重复字符进行受限归一化；
- 重复比例过高时安全失败；
- OCR 失败不会把未校验内容发送给模型；
- 不记录简历正文、图片内容或完整路径。

本地合成截图 DOCX 测试已通过。

## 7. 修复管理员归档和重新上传功能

完善管理员端简历和任务管理：

- 归档按 `student_id + request_id` 独立定位；
- 归档不再受任务是否已发布的错误限制；
- 归档操作幂等；
- 归档不会物理删除数据库、简历、题目或媒体；
- 已归档任务默认隐藏；
- 勾选“显示已归档”后可以查看和恢复；
- 新上传简历不会恢复旧任务的归档状态；
- 支持对已有学生重新上传 PDF/DOCX；
- 新文件保存为新的简历版本；
- 旧文件和历史任务继续保留；
- 上传后需要管理员手动点击重新生成；
- 上传和归档均写入审计记录。

## 8. 完成并发接口和转码压力测试

在隔离环境中进行了 10、25、50 个 Session 测试：

- 50 个 Session 接口并发：通过；
- 5xx：0；
- 缺失分片：0；
- 重复录制：0；
- 重复 finish：幂等；
- Worker 任务持久化和重启恢复：通过；
- 50 个 Session 合成测试峰值 RSS 约 84MB；
- Swap 基本未使用。

同时完成隔离 ffmpeg 测试：

- 10、25、50 个转码任务均成功；
- H.264/AAC 校验通过；
- duration 和 seek 校验通过；
- 单个 50 分钟转码任务内存约 110MB；
- 单 Worker 串行转码时，多个任务会产生明显排队。

因此当前瓶颈主要是转码队列速度，而不是内存容量。
