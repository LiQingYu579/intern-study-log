## 1. 首次钉钉登录自动开启

### 问题

旧逻辑要求管理员先点击"开始面试"创建 `in_progress` Session，学生首次钉钉登录才能进入体验。这导致一个尴尬的局面：题目审核通过、版本正常发布、TTS 全部就绪、学生也完成了钉钉绑定，但只要管理员没点那个按钮，学生看到的依然是"本次体验尚未开放"。

### 修复

调整自动创建 Session 的判断逻辑：当题目审核通过、已发布且 TTS 全部就绪时，学生首次钉钉登录自动创建新的 `in_progress` Session。已有进行中 Session 则继续复用，重复刷新和 OAuth 回调不会创建多条。已完成、失败或中断的历史 Session 不会被自动重开。管理员"重新开始面试"的入口保持不变，未发布、未审核或 TTS 未完成时仍正常拦截。

### 测试覆盖

首次登录自动创建、重复登录幂等、进行中 Session 复用、终态 Session 不自动重开、管理员重新开始、并发请求不创建重复 Session、未发布/未审核/TTS 未完成拦截，共 7 组场景。

## 2. TTS 未完成后的进入状态

### 问题

真实体验中，学生在 TTS 尚未全部生成时扫码登录，系统正确拦截并提示"语音还未生成完毕，请稍后再试"。但等 TTS 完成后重新进入，又出现新问题：开场白没播、第一题背景材料和题目没播，直到点击麦克风进入下一题后音频才恢复正常。

### 排查

根因在于系统没有严格区分以下几种状态：TTS 未完成、Session 已创建但题目未初始化、音频已就绪但浏览器自动播放被拦截、当前题目已真正开始。这几种状态混在一起，导致页面在错误时机推进流程。

### 修复

TTS 未完成时停留在准备状态，不进入题目流程；音频真正播放成功前不标记为已播放；页面刷新不跳过开场白、背景材料或第一题；浏览器自动播放被拦截时提供点击恢复入口；初始化失败时不推进题目、不增加暂停次数。

## 3. 初始化空 Session 被误判暂停

### 问题

初始化阶段的空 Session（无答题记录、无题目活动、无录音分片、无有效浏览器 lease）也参与了连接超时判断。创建后约 3 秒就会被标记为 `connection_lost`，导致学生首次进入就看到"继续体验"，点进去又变成"体验已暂停"，暂停次数被错误增加，管理员看板也出现实际无人操作但状态为暂停的 Session。

### 修复

`0/0` 且无实际答题活动的空 Session 不再被当成可恢复面试；初始化阶段不触发自动暂停；心跳宽限时间从原来的值调整为 150 秒；只有真正进入题目并开始答题后，连接中断才被记录。页面刷新、设备检测和短暂网络抖动不再直接增加暂停次数。前端会清理旧 Session 的浏览器状态，新 Session 不继承旧的暂停次数、进度或本地状态。

## 4. 管理员看板状态口径修复

### 问题

排查发现同一学生在数据库中同时存在历史 `completed` Session 和后续空的 `in_progress + paused` Session。旧看板 SQL 优先选择 completed 记录，导致真正在进行中的 Session 被遮蔽——看板显示"正在答题 0、暂停中 0、待恢复 0"，但数据库里实际有 `in_progress + paused` 记录。部署安全检查和管理员页面结果也对不上。

### 修复

统一状态选择规则：同一学生、同一发布版本下优先显示真实的 `in_progress` Session；没有进行中 Session 时才显示最近的终态记录。completed 不会再遮蔽后续活动 Session。Dashboard summary、学生名单和详情页使用同一套规则。

另外发现一条孤立的空 Session（`0/0`、无答案、无录音、无有效 lease、暂停原因为 `connection_lost`），确认属于初始化阶段误产生的孤立记录后，通过管理员审计逻辑标记为 `interrupted`，未删除数据库记录或媒体文件。

## 6. 暂停后接管失败

### 问题

ID315 测试中发现：学生主动暂停后返回体验准备页，点击"接管本次体验"失败，页面提示旧页面可能仍在录制，需刷新浏览器才能进入。第二次暂停时又可以不刷新直接恢复，行为不一致。

### 排查

根因是浏览器 Web Lock 的释放没有等待完成，接管失败后前端没有重新读取服务端 lease，旧页面和新页面之间存在短暂状态不同步。

### 修复

暂停流程等待 Web Lock 释放完成后再继续；接管按钮重新读取服务端权威状态；支持安全重试；旧页面确实仍在录制时继续拒绝接管；旧 lease 已失效时无需刷新即可接管。同一时间只允许一个有效录制 owner，重复点击接管不会创建重复 Session 或重复媒体。

## 7. 最后一题完成后 Live2D 消失

### 问题

ID315 测试中发现前面题目进行时 Live2D 正常显示，但完成最后一题后 Live2D 消失，页面回退为静态默认头像。

### 修复

根因是结束流程直接调用了 `releaseLive2D()`，导致实例在完成状态切换时被销毁。修复后：完成最后一题时保留当前 Live2D 实例并继续挂载到完成页面；只有页面真正卸载时才销毁实例；只有初始化失败或资源不可用时才显示默认头像。完成状态、录音停止、媒体上传和页面刷新不会误删 Live2D。

## 8. 主动暂停被错误计入切屏

### 问题

ID315 测试中学生主动点击暂停后，页面出现切屏提示，切屏次数增加了 1 次。根因是主动暂停的抑制标志设置晚于暂停确认弹窗，导致暂停过程中的页面失焦、录音停止或状态切换被误判为切屏。

### 修复

点击主动暂停时立即设置抑制标志；暂停、恢复和设备检测阶段不记录切屏；暂停期间的 `blur`、`visibilitychange`、`pagehide` 不增加切屏次数。只有真实答题阶段离开页面或切换标签页才记录。重复暂停、恢复、刷新和接管不会重复计数。ID315 的历史切屏次数保留原值，未做改写。
