## 5. 修复钉钉首次登录

生产日志确认，部分钉钉用户信息接口返回 `unionId`、`openId` 和 `nick`，但不返回 `name`。旧代码虽然提取了 `nick`，绑定逻辑却只读取 `name`，导致首次登录返回 HTTP 403，并显示“钉钉未返回实名姓名”。

修复后：

- 支持顶层及 `result`、`data`、`result.data`、`data.result` 等响应结构；
- 姓名字段按 `name -> realName -> nick` 的顺序提取；
- 姓名使用 NFKC Unicode 规范化、首尾空格清理和内部空白折叠；
- 已绑定用户直接通过唯一 `unionId` 登录，不再要求本次响应必须包含姓名；
- 未绑定用户只在姓名唯一匹配时自动绑定；
- 缺少姓名、同名或目标已绑定其他账号时安全拒绝，避免串号；
- 日志只记录字段存在性和类型，不记录姓名、unionId、openId 等具体值。

生产 Web 重启后已完成一次真实首次绑定验证：用户信息接口返回 200、回调返回 302、学生入口返回 200。

## 6. 完善浏览器关闭后的 Session 恢复

旧实现仅依赖 `sessionStorage` 中的录制键。浏览器被直接关闭时，服务端仍保留 active 录制记录，新页面会永久显示“当前体验已在其他页面录制”。

现已完善页面所有权和恢复机制：

- Chromium/Edge 优先使用 Web Locks API；
- 兼容降级使用 localStorage 租约和心跳；
- 页面正常关闭时主动释放，浏览器崩溃时租约过期后自动释放；
- 新页面恢复同一个 Session，不创建重复 active Session；
- 支持明确的页面接管，旧页面的后续上传会被拒绝；
- 已上传分片、答案和已完成题目不会被覆盖；
- 当前题倒计时由服务端 deadline 控制，浏览器刷新不能重置；
- 离开期间当前题超时后，只将该题处理为超时，再进入下一道未完成题；
- 后续题目不会在无人操作时连续自动过期。

## 7. 增加暂停和继续体验机制

根据业务方提出的中途离开需求，已增加暂停/恢复能力：

- 学生可以主动暂停并安全离开；
- 暂停时保存当前题目、答案、阶段和剩余作答时间；
- 暂停期间服务端 deadline 冻结；
- 再次钉钉登录后恢复相同 `session_id`；
- 设备检测完成后继续当前题，而不是从头开始；
- 材料或题干播报阶段恢复时从当前阶段开头重新播报；
- 回答阶段恢复保存的剩余时间；
- 主动暂停最多成功 2 次，第 3 次暂停请求被拒绝，但 Session 和媒体不会销毁；
- 单次暂停超过 30 分钟的部分会从当前题剩余时间中扣除；
- 浏览器关闭、崩溃或断网时，根据最后心跳加 3 秒宽限进行自动暂停；
- 普通切屏不会触发暂停，仍按切屏行为记录。

暂停和恢复会产生多个原始录像分段。系统保留每个分段，并计划在体验结束后由 Worker 按顺序合并为一个最终 MP4；暂停期间不补黑屏或静音。

## 8. 建立正式发布后的 TTS 预生成体系

生产实测发现，外部 TTS 在冷缓存时通常需要约 15–38 秒，旧前端 12 秒超时会提前判定失败。已先完成现场播放修复：

- TTS API 等待上限延长至 60 秒；
- prewarm 请求携带当前 `session_id`；
- 开场白、背景材料和题干继续严格串行播放；
- 缓存缺失时保留安全的按需生成兜底。

随后新增正式发布后的持久化预生成体系：

- 只有当前有效、已审核、正式发布且未归档的版本可以生成；
- 发布事务成功后幂等创建后台任务，不同步阻塞管理员请求；
- 任务和音频条目写入 SQLite，Worker 重启后可以继续；
- 缓存身份包含学生、Request、内容类型、内容标识、文本摘要、模型、音色和格式；
- 缓存身份不依赖临时 Session；
- 使用稳定 HMAC 保护缓存身份；
- 最终文件保存为单声道 MP3、48kbps；
- 临时 WAV 不长期保留；
- 已成功音频不会重复生成，失败时只重试失败条目；
- 旧 Request、未发布、已归档和 obsolete 任务不会被当前 Session 使用；
- 管理员详情显示待生成、生成中、已就绪和失败状态。

## 10. 排查暂停后多段录像合并失败

已对 Session `ijYc4MCkPxn-ep8cRH8ANc0s-35BCisf` 完成只读诊断。

该次体验：

- 完成 15/15 题；
- 暂停 2 次；
- 产生 2 个录像分段；
- 第二段转码成功；
- 第一段转码失败；
- 最终分段合并未真正启动。

第一段原始媒体实际完整：

- 3 个分片连续，无缺失；
- 总大小约 2.77MB；
- WebM 初始化头有效；
- VP8 视频和 Opus 音频均存在；
- ffmpeg remux 返回 0；
- ffprobe 实际有效时长约 25.148 秒。

真实根因是时长估算错误：

- 前端 `dataavailable` offset 实际接近分片结束时间；
- 后端错误地执行“最后 offset + 中位分片间隔”；
- 预期时长被高估为 34.509 秒；
- 校验下限被抬高到 27.607 秒；
- 实际有效的 25.148 秒短尾录像因此被误判为截断。

同时发现管理员“重新合并”按钮错误提交最新的第二段 recording ID，因此此前只重跑了已经成功的第二段，仍无法恢复第一段。

该问题属于暂停或关闭时产生短尾分片时的通用代码缺陷，不是本次媒体随机损坏。原始分片全部保留，具备重新转码和合并条件。
