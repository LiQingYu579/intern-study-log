# AIPQ 项目接手开发、全程媒体保存与单机性能优化记录

## 1. 修复全程录音录像链路

在原有逐题录音、录像的基础上，继续完善全程媒体保存：

- 新 Session 使用持续 MediaRecorder；
- 面试过程中按约10秒上传视频分片；
- 题目切换不会停止全程录制；
- 记录面试开始、材料播报、题目展示、回答和中断事件；
- 数字人 TTS、学生麦克风和摄像头画面统一进入全程录制；

- 学生结束面试后由后台完成 finalize 和转码。

## 2. 定位并修复视频只有几秒的问题

此前出现过：

- 分片数量完整；
- 视频文件体积较大；
- 但最终 MP4 只有约9～10秒；
- Windows播放器无法查看完整时长或拖动进度。

排查确认，浏览器 MediaRecorder 产生的 WebM 分片并不是多个独立的完整 WebM 文件：

- 第一个分片包含 WebM 头；
- 后续分片主要是 Cluster 数据；
- 使用 concat demuxer 当作多个独立 WebM 处理时，ffmpeg 可能只读取第一段；
- 即使返回码为0，也可能生成错误的短视频。

现已改为：

```text
按 manifest 顺序读取全部分片
→ 重建完整 WebM 流
→ remux 为带 duration 和索引的中间容器
→ 生成 H.264/AAC MP4
→ 使用 ffprobe 校验后才设置为主视频
```

短输出、缺少音视频轨道、duration异常或分片不完整时，不再误判为成功。

## 3. 完善持久化转码任务

为避免转码依赖当前进程，新增持久化转码任务机制：

- 增加 `session_transcode_jobs`；
- 记录任务状态、重试次数、开始时间、结束时间和错误类型；
- 支持 `queued`、`running`、`succeeded`、`transcode_failed` 等状态；
- Worker 重启后可以恢复未完成任务；
- 重复点击“重试转码”不会创建重复任务；
- 转码过程使用临时文件和原子替换；
- 失败时保留原始分片、WebM和音频；
- 管理员页面可以轮询任务状态。

同时修复了旧任务被错误复用的问题。明确重试时，已经完成但实际无效的旧任务会重新进入队列。

## 4. 完成 MP4 交付验证

对已有57个视频分片进行核对：

- 分片数量：57；
- 索引：0～56；
- 缺失分片：0；
- 实际读取分片：57；
- 重建后的媒体时长约570秒；
- 生成 MP4 时长约570.571秒；
- 视频编码：H.264；
- 音频编码：AAC；
- 文件大小约509.9MB；
- 浏览器播放和管理员时间跳转正常；
- 下载到本地后可以查看时长并拖动播放进度。

此前的9.96秒短视频不会再被作为有效主视频。

## 5. 将 MP4 作为主交付媒体

根据后续 pipeline 的实际需求，调整媒体交付策略：

- 完整 MP4 作为 Session 的主媒体；
- pipeline 只读取已经通过校验的 MP4；
- WebM作为归档附件保留；
- manifest和timeline只作为后台审计数据；
- 管理员页面不再把题目时间轴作为主要用户功能；
- 不再依赖人工按题目操作视频；
- 转码成功后自动进入可播放、可下载状态。

这样可以简化管理员操作，也避免时间轴异常影响视频交付。

## 6. 按单台虚拟机进行资源优化

当前生产环境确定使用单台虚拟机：

- 4核 CPU；
- 8GB 内存；
- 约550GB磁盘。

没有增加新的虚拟机或运行节点。

转码配置调整为：

- 转码 Worker 默认并发：1；
- ffmpeg 使用2个线程；
- systemd 设置较低 CPU 优先级；
- 避免转码过程占满4核 CPU；
- 出题并发和视频转码并发分开管理。

学生面试录制和后台视频转码相互解耦，转码任务进入队列，不会阻塞学生完成面试。

## 7. 降低录制和转码存储占用

新录制参数调整为：

- 摄像头约640×480；
- 约24fps；
- 视频码率约1Mbps；
- 音频码率约96kbps；
- 使用VP8/Opus WebM分片。

MP4使用：

- H.264；
- `veryfast`；
- CRF23；
- `fps_mode passthrough`；
- 限制最大码率；
- AAC 96kbps；
- `faststart`。

目标是在保持人像画面和语音清晰度的前提下，把50分钟面试的最终占用控制在约600～850MB以内。

后续不长期保留三份完整内容：

- 原始分片；
- 重建WebM；
- MP4。

分片在媒体校验成功后保留安全期，之后再清理。清理命令当前默认为 `dry-run`，不会直接删除文件。

- 不调用接口、不启动ffmpeg、不删除媒体。
